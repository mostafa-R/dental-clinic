CRITICAL
1. checkPermission.js:70 — clinic_admin بيعدي RBAC بالكامل

isSystemAdmin: roleDoc.isSystemAdmin || ['site_admin', 'clinic_admin', 'super_admin'].includes(roleKey)
لو المستخدم عنده role = clinic_admin، هو بypass كل صلاحيات الـ RBAC حتى لو الـ Role document بتاعته بيقول isSystemAdmin: false. ده معناه إن أي clinic_admin يقدر يعمل أي حاجة.

2. siteAuth.js — مش بيتشيك tokenVersion لو الـ site admin غير باسورد، التوكن القديم فضّل شغال. مفيش tokenVersion check في protectSite (siteAuth.js:31).

3. validate.js:15 — extra fields بتنعدم من req.body

for (const key of Object.keys(result.data)) { req.body[key] = result.data[key]; }
الـ Zod schema بيعمل strip للـ unknown fields من result.data، بس الـ extra fields الأصلية في req.body فضلت موجودة. يعني لو الـ schema بيقبل name بس الـ client بعت name + role، الـ role هيعدّي.

4. treatmentPlan.service.js:49 — Invoice creation + stock deduction مش في transaction generateInvoiceFromPlan بيعمل Invoice.create() وبعدين بيخصم الـ inventory في operations منفصلة. لو الـ deduction فشل، الفاتورة اتعملت بالفعل ومفيش rollback.

5. wallet.service.js:5-15 — getOrCreateWallet race condition

let wallet = await Wallet.findOne({ patient: patient._id });
if (!wallet) {
  wallet = await Wallet.create({...});
}
طلبين concurrent ممكن يشوفوا إن مفيش wallet، والاتنين يحاولوا يعملوا create. الـ unique index هيرجع duplicate key error بدل ما يرجّع الـ wallet الموجود.

HIGH
6. auth.controller.js:21 — Logout مش بي invalidate الـ access token بي bumps الـ tokenVersion (اللي بيلغي الـ refresh token)، بس الـ access token (15 دقيقة) فضّل شغال. ده design trade-off بس ممكن يكون مش مقبول في بعض الحالات.

7. invoice.service.js:282-297 — Commission بتتخلق per-payment مش per-invoice كل payment بيتعملها commission record جديد. يعني لو مريض دفع 5 مرات على نفس الفاتورة، الدكتور هياخد 5 عمولات على نفس الفاتورة.

8. invoice.service.js:373-448 — Refund مش بيرجع للمكان الأصلي لو المريض دفع بالكارت وعمل refund، الـ refund بيروح للـ wallet (لو method='wallet') أو كاش. مفيش logic بيرجع الفلوس لنفس طريقة الدفع الأصلية.

9. invoice.model.js:159-173 — paidAmount distribution ممكن يخسر أرقام بسبب الـ rounding الـ proportional allocation بيجمع round2() في كل iteration، والباقي (remaining) ممكن يتأثر. في فاتورة بـ 3 items ومبلغ صغير، ممكن تلاقي paidAmount != sum(item.paidAmount).

10. installmentPlan.controller.js:126 — مش بيقيّد الـ installment plan بالـ branch
